# 截图中的虚构论文：原因与修复

首次定位基于 main 提交 `f2e9be7c6246dd9684c9066049e71d12d82ffe69`；提交前已合入远端 `d8286c1` 的主页与资料包更新。

## 为什么会出现这些标题

截图里的 `A Unified Study of ...`、`Arxiv Evidence for ...`、`Openalex Evidence for ...` 来自 `src/paper_agent/adapters/demo.py` 中的 `DemoRetriever`。它把用户问题截取后拼进示例标题，配上示例作者、虚构 DOI 和 example.org 下载地址；这些不是检索到的论文。演示排序还会随输入文字变化，所以更换提示词后分数也会变。

`demo` 和 `ranking` 两种装配模式都使用演示检索。原版在未配置 `PAPER_AGENT_ENV` 时默认进入 `demo`；本地 `.env` 不随 Git 分发，且原版只在启动工作目录查找它。从其他目录启动、漏配文件，或者终端环境变量仍为 `demo` / `ranking`，都可能出现截图现象。仅凭截图不能区分具体是哪一种配置原因。

最新版已经包含针对这条 5G/6G 中文问题的双语关键词改写和回归测试，但只有 `retrieval` / `production` 装配会调用真实检索组件。

## 这次修改

- 未配置模式时默认 `production`，接入六个真实来源和实际下载处理。
- 当前工作目录没有 `.env` 时，读取本源码仓库根目录的 `.env`；显式路径和已有环境变量仍有优先权。
- 界面按实际 Settings 缓存 Agent，配置变化后不再复用另一模式的旧实例。
- 显式演示检索显示醒目提示；示例论文标题、报告和结构化结果警告均标明演示性质。
- 增加默认启动、配置文件定位、两种 5G/6G 问法、来源为空/失败不编造论文、演示标识和界面缓存的回归测试。

## 使用方式

在仓库根目录打开本地 `.env`，确认：

```dotenv
PAPER_AGENT_ENV=production
```

首次使用且还没有 `.env` 时，复制 `.env.example` 为 `.env`；已有配置不要覆盖。检查启动终端是否设置了优先级更高的 `PAPER_AGENT_ENV=demo` 或 `ranking`，将其改为 `production` 或移除。停止原服务，再启动：

```bash
python -m streamlit run src/paper_agent/ui/app.py
```

确认侧栏显示 `production：六源真实检索`，重新点击开始研究。历史结果不会因更新代码而自动变成真实结果。

未配置模型 Key 时仍会访问真实论文来源，查询使用内置双语词典，单篇总结和综述使用规则降级。其他提示词可能生成不同的查询与排序；不能保证不同表达逐篇返回相同论文，但不得再把演示标题当成真实结果。
