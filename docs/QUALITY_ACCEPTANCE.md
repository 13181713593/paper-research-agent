# 完整研究流程：修复与验收记录

日期：2026-11-08。此轮在默认启用真实检索的修复之后，继续检查从召回到报告的完整链路。

## 问题与处理结果

| 检查项 | 处理 | 验证与边界 |
| --- | --- | --- |
| 演示论文混入真实研究 | 默认 production；演示数据明确标记 | 原修复已提交；生产装配回归验证不使用 DemoRetriever |
| 公开全文漏取 | 补充 SciTePress 动态下载页对应的公开 PDF 候选，下载仍检查 PDF 格式 | 实际取得 DOI `10.5220/0012590800003711` 的全文；不执行任意页面 JavaScript |
| 缺摘要 | 从论文落地页元标签/摘要容器补查，或从解析全文的显式 Abstract 标签回填 | 支持 PDF 将 Abstract 与作者信息合并为一段的情况；不覆盖已有摘要，不从标题编造摘要 |
| TLS 证书错误 | HTTPX 使用系统信任库，保留证书和主机名验证 | 原证书失败的公开 PDF 在系统信任库下取得 HTTP 200；不关闭 TLS 校验 |
| PDF 编码与缓存 | 增加 CFF 字体解码依赖 fonttools，更新转换版本以失效旧解析缓存 | 原始 PDF 缓存保留；文本层缺失的扫描件仍不能冒充完整正文 |
| 章节识别导致总结空白 | 无标准方法标题时从正文显式方法句中抽取；摘要与方法字段分开 | 不把参考文献当作本文方法；降级结果明确标记 |
| 模型编造或改写引文 | 给原文切片分配稳定编号，模型选择编号，程序附上原文；引用另作文字匹配 | 不存在的编号/原文不匹配会重试，仍失败则降级；文字匹配不验证因果关系、页码或实验复现 |
| 综述没有回答比较重点 | 单篇总结增加架构、卸载/分配策略、资源约束和评价指标；报告生成相应矩阵 | 正文要求回应研究重点，区分各架构、决策变量、目标与适用条件，不把不同实验条件下的数字用于横向排名 |
| 失败模板凑字数 | 无模型/失败时只生成有证据的简明摘录和对照，不强行填到 1000 字 | 报告注明生成方式与质量限制；流水线保留部分完成状态 |
| 配置与文档不一致 | 查询规划 Key 缺省复用本地总结 Key；显式空构造参数仍可关闭模型 | 测试隔离本地 .env，不将真实 Key 混入离线用例 |
| 来源配额与请求过多 | 同身份同请求成功结果缓存 5 分钟，最多 32 项；限制布尔来源短语数；保留 Retry-After/预算和多源继续机制 | 长短主题均限制查询计划规模；外部限流不能由应用解除，仍如实记录来源缺失 |
| Semantic Scholar 日期排序 | 日期排序使用官方支持 sort 的 bulk 接口，不发送其不支持的 limit，并在本地截断返回数据 | 普通相关性检索仍使用 relevance 接口；匿名配额不足时不把请求失败解释成无文献 |
| 论文类型与页面误读 | 标注 Research Square、arXiv DOI/仓储版本；页面显示材料缺失、模型降级与来源警告 | 收录/发表类型不等于研究质量认证；执行完九阶段不等于科学结论已验证 |

## 验收方法

`scripts/validate_research_quality.py` 分别检查：流程到达报告、论文数量、摘要、全文文件、实际模型总结、实际模型报告、正文长度、原文引文匹配，以及资源主题下的比较字段。仅有文件或阶段成功不能通过验收。

```bash
python scripts/validate_research_quality.py --live --idea '请你帮我调研在5G/6G网络环境下，云边协同架构中的任务卸载与计算资源调度算法，并重点分析不同架构下的资源分配策略' --require-resource-comparison --output-dir artifacts/5g6g-quality
python scripts/validate_research_quality.py --live --idea '场景文本检测与识别' --top-k 2 --pool-size 8 --source-limit 8 --output-dir artifacts/ocr-quality
```

两种模式均需显式选择。`--live` 会联网并调用本地配置的模型；`--reaudit <pipeline.json>` 仅复核已有本地结果，不重新检索或调用模型。结果写入 Git 忽略的 artifacts 目录。请勿将带密钥的本地配置提交到仓库。

## 实测结果

- 5G/6G 例子：5 篇均有摘要和全文，5 份单篇总结实际使用模型，1369 字中文模型综述，架构、分配策略、约束和指标字段齐备，原文引文全部匹配。首次验收脚本将“已说明架构，但未明确更细的编排机制”误判为整个架构字段缺失；修正判定并增加回归后，对同一份真实输出复核通过，没有改写原综述来使检查通过。
- 场景文本检测与识别：另一主题真实运行，2 篇均有摘要和全文，模型总结、模型报告、正文长度和原文引文匹配均通过，未用资源调度字段要求不适用的主题。
- 全量离线回归：513 项通过，3 项可选联网/付费冒烟跳过；Ruff 与差异空白检查通过。

## 不能由这些检查保证的事项

这些结果证明上述案例及回归覆盖的行为通过，不代表检索穷尽所有相关论文，也不代表任何未来输入都能取得全部全文。第三方限流、登录权限、付费墙、服务中断、扫描件和公式解析限制仍可能影响结果，程序应显示证据边界。

原文引文匹配和模型成功调用不等于科学结论正确、实验可复现或跨论文数值可直接比较。对外研究结论仍需结合原论文人工复核。模型 Key 只在用户本地 .env 中；仓库不包含用户密钥或本地运行产物。
